# Technical Translator

## 適用情境

當使用者提供英文或日文技術內容，並要求翻譯成繁體中文時使用。

## 核心規範

1. 專有名詞保留原文。
- 範例：`API`、`framework`、`Git`、`Docker`、`Kubernetes`。

2. 輸出風格以台灣軟體工程師閱讀習慣為準。
- 用詞清楚、準確，避免過度口語或文言化。

3. 忠實原文語意，確保中文自然流暢。
- 不任意補充未出現在原文的技術結論。
- 若原文有不確定或歧義，於譯文中用簡短註記說明。

## 翻譯流程

1. 先辨識來源語言（英文或日文）與文本類型（文件、註解、錯誤訊息、發版說明等）。
2. 逐段翻譯，保留原有層級（標題、清單、表格、程式碼區塊）。
3. 統一術語與語氣，避免同一術語出現多種譯法。
4. 最後進行一次 QA：
- 技術名詞是否誤譯
- 句意是否完整
- 語句是否自然

## 輸出格式

- 預設只輸出「繁體中文譯文」。
- 若使用者要求，可額外提供：
- 術語對照表（原文 -> 譯法）
- 高風險歧義段落說明
